# API 调用链

`src/generated/api.types.ts` 由 `api/openapi.yaml` 生成，**只有 TypeScript 类型，运行时不会执行**。`src/generated/api.ts` 是手写的浏览器请求层；页面调用它导出的函数，函数通过 `fetch` 调用 Next.js 路由。路由引用生成类型检查响应结构，再调用业务函数。修改接口时先改 OpenAPI YAML，运行 `npm run api:generate`，然后更新请求层与路由。

## 面板数据：`GET /api/monitor`

```text
浏览器 src/components/dashboard.tsx 的 useEffect
  → getMonitor({ scope, minutes, step }, signal)         src/generated/api.ts
  → getJson<MonitorResponse>() → fetch('/api/monitor?...')
  → GET(request) → handleGet(request)                   src/app/api/monitor/route.ts
      → 校验 scope、minutes、step；失败返回 400
      → getDashboard(scope, minutes, step)              src/lib/prometheus/business.ts
          → loadDashboard(): 并发查询 CPU、内存、网络、可用性、告警等
          → query()/queryRange()/getAlerts()             src/lib/prometheus/http.ts
          → HTTP 请求 Prometheus；失败向上抛出
      → NextResponse.json(Dashboard)；失败返回 502
  → getJson() 解析 JSON，检查 HTTP 状态，抛出错误或返回 Dashboard
  → dashboard.tsx 更新 data、error、loading 状态
```

首页首次加载还有一条服务端路径：`src/app/page.tsx → getDashboard() → Prometheus`，结果作为 `initialData` 传给 `Dashboard`。浏览器挂载后仍会通过上述 API 路径刷新；自动刷新间隔为 30 秒。

## 节点状态：`GET /api/node-status`

```text
浏览器 dashboard.tsx 的 3 秒轮询
  → getNodeStatus(signal) → getJson() → fetch('/api/node-status')
  → GET()                                                src/app/api/node-status/route.ts
      → DEMO_MODE=true：返回 { statuses: null }
      → getNodeAvailability() + getNodeInventory()        src/lib/prometheus/business.ts
      → query() → Prometheus                              src/lib/prometheus/http.ts
      → 按节点名和地址合并状态；失败返回 502
  → getJson() 返回 statuses；dashboard.tsx 更新 nodeStatuses
```

轮询失败时页面保留上一次成功的节点状态。

## 告警列表：`GET /api/alerts`

```text
浏览器 src/components/alerts-page.tsx 的 load()，每 30 秒刷新
  → getAlerts() → getJson() → fetch('/api/alerts')
  → GET()                                                src/app/api/alerts/route.ts
      → DEMO_MODE=true：返回 { alerts: [] }
      → 已配置 ALERTMANAGER_WEBHOOK_TOKEN：
          getPushedAlerts() → getDatabase().query()       src/lib/alertmanager.ts、database.ts
          → PostgreSQL 活动告警表
      → 未配置 token：getResourceAlerts() → getAlerts() → Prometheus
      → 将告警映射为 AlertRow；失败返回 502
  → getJson() 返回列表；alerts-page.tsx 更新 alerts、source、error
```

这里的 `getAlerts()` 有两个同名函数：`src/generated/api.ts` 中的是浏览器请求函数，`src/lib/prometheus/http.ts` 中的是访问 Prometheus 的服务端函数。

## Alertmanager 推送：`POST /api/webhooks/alertmanager`

此接口由 Alertmanager 调用，**不经过浏览器请求层 `src/generated/api.ts`**。服务端路径如下：

```text
Alertmanager POST JSON + Bearer token
  → POST(request)                                        src/app/api/webhooks/alertmanager/route.ts
      → 验证 token、Content-Type、请求体大小
      → parseWebhook(JSON)                               src/lib/alertmanager.ts
          → 验证 v4、告警字段、批次条数
          → 提取 fingerprint、对象标签，并保留原始数据
      → applyWebhook(alerts)                              src/lib/alertmanager.ts
          → getDatabase().connect()                       src/lib/database.ts
          → BEGIN；事务锁；firing 时 INSERT/UPDATE，resolved 时 DELETE
          → 查询活动告警数量；COMMIT，失败时 ROLLBACK
      → NextResponse.json({ received, active })；失败返回对应错误码
```

浏览器请求层的 `getJson()` 只负责 JSON 解析和 HTTP 错误处理。响应结构在服务端由生成的 OpenAPI 类型进行编译期检查；它没有对网络返回的 JSON 做运行时 schema 校验。
